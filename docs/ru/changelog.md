## 0.1.0 — реализация в процессе

### Документация

- Английский README переработан для игроков, добавлена полная русская документация в `docs/ru`; каноническая документация сохранена на английском с навигацией между языками.
- Добавлены полные русские журнал изменений, план разработки и архитектура в `docs/ru`; сохранены технические свидетельства, команды и ограничения приёмки, восстановлены локальные ссылки навигации между документами.
- Исправлены английские и русские инструкции первого запуска: бочка мастерской регистрируется до мастерской, а повёрнутый строительный буфер — до запуска стройки.

### Структура пакетов Java

- Все пакеты и пути исходников Java для рабочего кода и тестов сокращены до `colonyloom.*`, включая нативные GameTests; импорты, полные ссылки и архитектурные проверки перенесены без совместимых псевдонимов. Группа публикации Gradle, идентификаторы модов и схемы сохранения не изменились.
- Проверка `check assemble :colonyloom-neoforge:dedicatedSmoke` выполнена за 5m 9s: все задачи модульных тестов и компиляция нативных фикстур — PASS; запуск выделенного сервера только с рабочим кодом/контент/метрики/штатная остановка/освобождение ресурсов среды выполнения и все три случая отказа сохранения — PASS (`dedicated-1791693866499`, checkoutUnchanged=true). Полные нативные, графические или масштабные прогоны для этой миграции только пакетов не выполнялись.

### Gate T — текущие технические исправления (приёмка ожидается)

- Восстановлены отсутствовавшие локальные объявления физического сервиса; нативные рабочие классы компилируются без фиктивных значений размещения по умолчанию.
- Навигация теперь обнаруживает допущенные готовые запросы WAITING в пределах существующих квантов/задержек повторов, опрашивает движение только после применения и отвечает за очистку ожидающего запроса до входа в вызовы бэкенда. Отмена точного запроса и защита от реентерабельных преемников предотвращают движение от устаревшего применения, подмену потребности и утечки ресурсов; ошибки бэкенда сохраняют исходное исключение с подавленными ошибками очистки.
- Добавлены регрессионные тесты движения/свойств потребителей для отмены/замены применения, вытеснения позиции, потери готовности и границ очистки, выбрасывающих исключения. Полная приёмка нативных, жизненных, графических, калибровочных, платформенных и масштабных сценариев на совпадающих исходниках всё ещё ожидается.
- Физические шаги строительства, производства, доставки и питания сохраняют зафиксированные полномочия работы/жителя/эпохи через обратные вызовы; устаревшие шаги до побочного эффекта ничего не расходуют, а изменившиеся нативные стороны сохраняют свидетельства восстановления без повторного выполнения. Назначенные продолжения WAITING разрешают только сохранённую навигацию, но не физические расходы.
- Исправлено голодание повторных попыток получения строительных материалов: ожидание в пределах существующей задержки 20 тиков больше не сдвигает срок бесконечно. Текущий нативный прогон проходит общую отмену партии/излишки, вытеснение питанием, паузы сканирования оплаченного выпуска/подбора, отзыв покрытия, прибытие за едой после смещения и все 63 исходных нативных маршрута.

### Этап 05 — физическое строительство и восстановление

- `/colonyloom build <colony UUID> colonyloom:stair_strip <pos> <0|90|180|270>` допускает одну компактную строительную цель из шестнадцати блоков и точную резервацию цели. Строители ходят между преобразованными рабочими точками, используют реальные материалы из меню NPC, ждут недостающие предметы и сохраняют размещённые блоки/имущество при отмене. Складская экономика или виртуальный буфер здесь не вводятся.
- Ограниченные по размеру стандартные NBT StructureTemplate вместе с метаданными JSON предоставляют неизменяемые дескрипторы блоков/предметов и канонические закреплённые дайджесты. Закреплённые версии используют общие компактные палитры, сохраняют принятые версии при перезагрузке и соблюдают ограничения в 64 версии/64 МиБ. Тестовые ресурсы из четырёх ступеней используют тот же формат; производственные маркеры — `work_origin=(0,0,1)` и `delivery_buffer=(-1,0,0)`.
- Реальное использование предмета заимствует стопку из слота NPC через несохраняемого исполнителя в режиме выживания с профилем текущего владельца, без операторского обхода или скопированного источника ресурсов. Повторно проверяются текущие индивидуальные полномочия, резервация цели, нативное состояние, реальный расход и область обработки сущностей; отменяемые события взаимодействия/размещения NeoForge могут запретить действие без расхода. Неожиданные физические результаты получают статус AMBIGUOUS; компенсации или повторного выполнения нет.
- Свидетельства эффектов размещения/смерти защищены маркером незавершённой сессии. Проверка при восстановлении включает реальные состояния целей и дайджест мира для всей площадки; accept-world повторно проверяет наблюдения, сохраняет физическую реальность и закрывает старую цель. Неизвестные закреплённые версии/эффекты сохраняют исходные записи и зависимые обязательства. Проверенное уплотнение контрольных точек сохраняет свидетельства PREPARED/AMBIGUOUS, открытые цели и используемые закреплённые версии; ожидающий ввод-вывод NeoForge завершается перед проверкой DTO/принудительной заменой.
- Проверен сценарий аварий выделенного сервера: чистая остановка/перезапуск после двух блоков продолжается до четырёх точных блоков с нулевым количеством материалов NPC; отмена сохраняет два блока/две ступени; остановки JVM до/после изменения сохраняют независимо записанные стороны, блокируют восстановление, ничего не расходуют/не выдают в течение 100 тиков и никогда не повторяют действие после accept-world. Производственная смерть сохраняет четыре реальные выпавшие ступени и устойчивый эффект OBSERVED. Обслуживание при достижении порога во время работы сокращает 2048 свидетельств до сохранённого свидетельства PREPARED, сохраняя открытую площадку и устойчивый курсор.

Запускайте из корня репозитория с JDK 21: `./gradlew build` (PowerShell: `.\gradlew.bat build`). Задачи разработки Minecraft относятся к `:colonyloom-neoforge`; запускайте физические регрессионные тесты через `:colonyloom-neoforge:runGameTestServer`. Для выделенных экземпляров требуется принятие Minecraft EULA владельцем среды; сборки не принимают её автоматически. `runServer` передаёт консольный ввод, поэтому `stop` выполняет штатное завершение работы. Сценарии только для разработки `/colonyloomtest identity setup|verify|conflict|recovery-check|isolation` требуют реально подключённого оператора и явно помеченного одноразового мира; они исключены из релиза.
